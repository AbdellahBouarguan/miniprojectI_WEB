Périmètre du sprint

Ce que l’on fait — et ce que l’on ne fait pas

P0 — obligatoire

  • Anomalies : correction + facture.
  • Réclamations client + traitement.
  • Paiement total d’une facture.
  • Dashboard impayés + évolution.
  • Agent + import annuel.
  • Vérification annuelle.
  • Notifications internes.
  • Rapport final.

P1 — si avance

  • Pièce jointe réclamation.
  • Filtres et pagination.
  • Notification e-mail.
  • Impression / export PDF.

P2 — reporté

  • Paiements partiels.
  • Multi-fournisseurs.
  • Dashboard avancé.
  • Réinitialisation mot de passe.
Règle : on livre d’abord tout le P0. Le P1 n’est pas bloquant. Le P2 est abandonné pour cette version.

Membre 1

Socle, base de données, Agent et intégration

J1 — Base et Agent

  • Figer le schéma cible : 12 tables.
  • Créer les migrations : agent, conso_annuelle, reclamation, paiement, notification.
  • Ajouter le rôle agent dans Traitement/Auth.php.
  • Session id_agent + redirection espace Agent.
  • Mettre à jour index.php avec les nouveaux contrôleurs.

J2 — Intégration

  • Fusionner les DDL dans sql/schema.sql.
  • Mettre à jour sql/seed.sql + Agent de démo.
  • Préparer les routes et la navigation.

J3 → J5

  • J3 : activer Réclamations, Paiements, Vérification, Agent ; merger les PR ; résoudre les conflits.
  • J4 : reset base, login 3 rôles, php -l, 404 et accès interdits.
  • J5 : tag v1.0-final, README, démo.

Critères d’acceptation

  • schema.sql et seed.sql s’importent.
  • Un Agent peut se connecter.
  • Un client ne peut pas accéder à l’Agent.
  • Toutes les routes sont protégées.
Fichiers : sql/schema.sql · sql/seed.sql · sql/migrations/ · Traitement/Auth.php · IHM/layout/header.php · index.php · MSD

Membre 4

Import annuel, Agent et vérification

J1 — Base et parser

  • Créer conso_annuelle : client, agent, eau, élec, année, date.
  • UNIQUE(id_client, annee).
  • Format : ID_Client,ID_Agent,ConsommationEau,ConsommationElect,Annee,Date_Saisie.
  • Valider l’entête + rejeter les lignes malformées.

J2 — Espace Agent

  • Upload .txt, vérifier le client.
  • Ignorer les doublons.
  • Rapport : insérés / ignorés / rejetés.
  • Fichier d’exemple.

J3 — Vérification annuelle

  • Page fournisseur + choix de l’année.
  • Comparaison mensuel vs annuel.
  • Écarts par client.
  • Notification via le service du Membre 2.

J4 → J5

  • Tests : fichier valide, entête invalide, ligne malformée, client inconnu, doublon.
  • Capture + section rapport.
  • Buffer corrections.
Fichiers : BD/ConsoAnnuelle.php · Traitement/Import.php · Traitement/Verification.php · IHM/import/ · IHM/verification/
Membre 5

Anomalies, facturation, QA et rapport

J1 — Flux anomalies

  • Toute anomalie bloque la facture.
  • Correction obligatoire + correction fournisseur.
  • Revalidation + contrôle du seuil.
  • Corriger AnomalieBD::corriger().

J2 — Facture après correction

  • Intégrer FactureService.
  • Transaction : correction + validation + facture.
  • Refuser une correction invalide.
  • Mettre à jour les vues.

J3 → J5

  • J3 : tests index inférieur, seuil, correction valide/invalide, doublon ; checklist.
  • J4 : QA, php -l, reset, desktop/mobile, captures, sections rapport.
  • J5 : compilation Tectonic, relecture, PDF final, démo.

Critères d’acceptation

  • Aucune facture avant correction.
  • Correction valide = facture.
  • Pas de doublon.
  • PDF final compilé.
Fichiers : Traitement/Anomalie.php · BD/AnomalieBD.php · Traitement/ConsommationTraitement.php · Traitement/FactureService.php · docs/latex/
